这段时间把站点又重新搭了一遍：羊皮纸底、墨蓝强调、照片墙、Live Photo 封面。东西齐了，人却还在半途——所以先写一篇碎碎念，**既是重新出发的备忘，也是正文排版的样例页**。右侧目录可以跳到各节，方便对照效果。

## 为什么又折腾一遍

旧站能写、能发，但有几处一直别扭：

1. **照片和文章是两套世界**——图只是附件，很难和文字同屏呼吸。
2. **Live Photo 在网页里几乎消失**——浏览器不认 HEIC/MOV，只好当静图。
3. **气质不统一**——组件多了之后，颜色、字重、边距开始各说各话。

所以这次收敛成几条硬规矩：单一品牌色、正文阅读节奏固定、Live 走本地导入脚本。细节写在仓库的 `docs/brand.md` 和 `docs/live-photo.md` 里，这里只记感受。

> 工具会过时，但「想留下什么」不会。站点只是外壳；外壳舒服了，才愿意多写一点。

## 近期在想的事

### 慢一点没关系

以前总想着「有空再写长文」，结果长文永远不来。现在更认 **短而真**：一段路上的念头、一张 Live、三行代码片段，都算数。

### 技术是手段

Astro、Cloudflare、内容集合……这些是脚手架。脚手架的意义是让 **写和看** 变轻，而不是再开一个要维护的产品。

### 照片墙当时间轴

隔空投送 → `pnpm live:import` → 自动进照片墙。文章需要封面时，frontmatter 里写一句：

```yaml
heroLive: '2026-03-30-094329'
```

slug 就是拍摄时间，不用再手工拷贝封面到 `assets`。

## 排版自检：基础元素

下面这些都是日常写文会用到的块，顺手验收一遍。

### 强调与行内

普通段落里可以夹 **加粗**、`行内代码`，以及 [站内链接](/photos/) 或 [外部链接](https://astro.build)。链接用品牌墨蓝，hover 会略亮一点。

键盘快捷键示例：保存用 `⌘S`，搜索用 `⌘K`（若你之后接了命令面板的话）。

### 无序与有序列表

**无序：**

- 羊皮纸背景，不刺眼
- 单色强调，不彩虹
- Live Photo 可点可按

**有序：**

1. 导入实况图
2. 写 frontmatter
3. 本地预览，再决定是否去掉 `draft`

**嵌套：**

- 写作
  - 草稿默认开启
  - 标签尽量少而准
- 发布
  1. `draft: false`
  2. 构建与部署
  3. 打开评论区看一眼

## 代码示例

### 命令行

```bash
# 新建草稿（MDX）
pnpm new:post "近期的一些碎碎念" --mdx --tags 生活,博客 --category 随笔

# 导入 iPhone Live Photo（HEIC + 同名 MOV）
pnpm live:import ~/Downloads/IMG_0258.HEIC --alt "西溪园区的樱花"
```

### TypeScript / 工具函数

```ts
import { getLive, listLive } from '../utils/live-photo';

// 按拍摄时间新 → 旧
const latest = listLive({ order: 'desc' })[0];

// 文章里嵌入某张 Live
const sunset = getLive('2025-04-18-181243');
console.log(sunset.photo, sunset.place?.label);
```

### 前端片段

```html
<figure class="live-photo" data-live-photo data-sound>
  <img class="live-photo__still" src="/images/live/…/photo.jpg" alt="…" />
  <video class="live-photo__motion" src="/images/live/…/video.mp4" playsinline></video>
  <button type="button" data-live-toggle>LIVE</button>
</figure>
```

行内对比：`const x = 1` 适合短标识；超过一两行就上 fenced block。

## 表格

| 能力 | 用法 | 备注 |
|------|------|------|
| 静图封面 | `heroImage: '../../assets/….jpg'` | Astro 会做图片优化 |
| Live 封面 | `heroLive: 'YYYY-MM-DD-HHmmss'` | 优先于 `heroImage` |
| 标签 | `tags: ['生活']` | 生成 `/tags/…` |
| 分类 | `category: '随笔'` | 可选 |
| 草稿 | `draft: true` | 生产构建默认不输出 |

小表也行：

| 断点 | 布局 |
|------|------|
| &lt; md | 单栏 |
| md+ | 正文 + 目录 |
| xl+ | 分享轨 + 正文 + 目录 |

## 正文里的 Live Photo

封面已经用了西溪樱花。正文里可以再嵌另一张——例如去年傍晚的海与山。悬停预览，点击或按住 **LIVE** 可带环境声。

<LivePhoto meta={liveSunset} alt="海与火山的日落" />

导入约定很简单：资源在 `public/images/live/<slug>/`，meta 在 `src/data/live/<slug>.json`，组件只认 `getLive(slug)`，不要手写拼路径。

## 图片（静图）

普通 Markdown 图片同样可用（路径相对站点根或外部 URL）：

若以后把配图放进 `src/assets`，也可以在 frontmatter 用 `heroImage` 走优化管线；正文大图目前以 `public/` 或远程 URL 最省事。
